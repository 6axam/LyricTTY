# Verification — 2026-11-05

This records observed behavior, not just the existence of interfaces.

## Automated checks

The complete integrated tree passes formatting, Clippy with warnings denied, 73 tests and a release build. CI installs mpv, D-Bus, Python and fonts to exercise local integration paths without a network service or user account.

- Pure tests: ordinary/enhanced LRC, Lyricsfile JSON/YAML, word boundaries and Unicode, easing, gap states, dark palette contrast, theme transitions, breakpoints and disk caches.
- Loopback HTTP/fake providers: request identity/encoding, fallback levels, bounded bodies, rate limiting, corrupt/expired caches and definitive misses versus errors.
- Private D-Bus: discovery, property/seek signals, capability guards, SetPosition and fallback, source disappearance/replacement and metadata caching.
- Mock mpv Unix IPC: request/reply correlation, partial messages, timeouts, malformed/disconnected socket, file transitions, one-time property seeding, playback/volume/seek, playlist boundaries and child/socket cleanup.
- Real mpv with `--ao=null`: generated tagged WAV playback, pause, seek, track replacement and playlist boundaries.
- TUI buffers: small/large/resized terminals, source disconnection, simultaneous source selection, paste safety and visible lyric clicks sent through a fake backend after resize.

## Live native playback

Tested public YouTube URL `https://www.youtube.com/watch?v=dQw4w9WgXcQ`: **Rick Astley — Never Gonna Give You Up**, duration about 213 seconds.

The opt-in native probe launched a real mpv with null audio output and confirmed Playing, Pause, Volume 25%, absolute seek and resumed Play by reading IPC events/state. Artwork was retrieved, decoded and produced text/background contrast 16.7:1. This verifies extraction and playback control, not the physical speakers.

LRCLIB lookup returned **line-synced lyrics, 58 nonempty lines, zero timed words**. A second lookup confirmed a cache hit. An incomplete community record initially returned one cue; the provider now checks matching releases when a multi-minute track has only a very sparse line record. No word timing was invented for this song.

Reproduce these opt-in network checks:

```bash
cargo run --example verify_backends -- native 'https://www.youtube.com/watch?v=dQw4w9WgXcQ'
cargo run --example verify_backends -- lyrics 'Never Gonna Give You Up' 'Rick Astley' 213
```

## Live browser / MPRIS

Real discovery found an existing **KDE Connect MPRIS source**, Paused, CanSeek=true. The personal source was only read, not controlled; its device identity is not published here.

For control verification, an isolated Firefox profile loaded the local `tests/fixtures/browser.html` media-session fixture with generated quiet audio. Firefox published `org.mpris.MediaPlayer2.firefox.instance_*`, Playing, CanSeek=true. The Rust MPRIS backend successfully issued **PlayPause** and **SetPosition(8 seconds)** and confirmed the resulting status/position. The test restored the initial playback state.

This verifies the actual Firefox/D-Bus path using a local media page. YouTube Music playback inside a browser was not independently acceptance-tested; the browser's MPRIS behavior and site metadata determine support. The in-app browser navigation to YouTube timed out, while yt-dlp/mpv succeeded.

`examples/verify_backends.rs` lists sources read-only with `mpris`; adding an explicit source ID exercises that player. Do not pass personal player IDs unless you intend to control them.

## Visual verification

The screenshot in `assets/hero.png` is an actual Kitty capture with the explicit `--demo` fixture. Its artwork is original procedural artwork generated by `examples/generate_demo_cover.rs`; lyrics in `examples/demo.lrc` are authored timing fixtures, including Cyrillic and an explicit instrumental gap. Kitty Graphics rendered the cover. Color testing removed the agent-inherited `NO_COLOR=1` only from the test process.

The ANSI fallback remains constrained by whole-cell fonts. Kitty now also has a pixel renderer: within-cell image placements move cached line images without doubled text. Latin and Cyrillic use a system bold sans font; complex scripts/combining graphemes preserve terminal shaping via fallback. Live visual quality should be judged in the target terminal; screenshots cannot demonstrate easing. Instrumental bars are ambient animation, not measured spectrum.

## Animation follow-up

Added nanosecond frame deadlines, default 60 FPS during animation, minimum-jerk easing with retarget velocity continuity, synchronized Kitty presentation, and pixel lyric placements. Tests cover sub-cell movement without PNG re-upload, clipped hit regions after font/viewport resize, hiding/reusing/freeing image placements, and click-to-seek dispatch through both renderers. The new path was visually checked in Kitty; its text is visibly larger and has no duplicated terminal rows.

`assets/smooth-lyrics.mp4` is a region-only recording of the running Kitty app, 954×1050 at 60 FPS, about 8.7 seconds. Capture damage/update reporting stayed around 60–61 FPS during playback. It contains only the original demo artwork and authored lyrics; no desktop-wide recording or audio was included.

The optional `cargo run --release --example animation_benchmark` measures 600 offline frames, including raster/color updates, PNG encoding and command serialization. It excludes terminal/GPU/display work and is not an FPS guarantee for other systems.

One local release-mode run at a 960×650-pixel lyric viewport measured median **0.099ms**, p95 **0.201ms**, and about **951KiB/s** of local graphics commands/data. This is terminal IPC traffic, not internet usage. The nominal 60 FPS frame budget is 16.67ms.
